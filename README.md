# forge-mcp

MCP-сервер поверх агентского API [Forge](http://localhost:3000). Один адаптер
вместо голого `curl` в каждом агенте: Claude Code, Codex и любой следующий
агент получают одинаковый набор инструментов, а ключ агента остаётся внутри
сервера и наружу не выходит.

## Инструменты

| Инструмент | Что делает |
| --- | --- |
| `forge_guide` | Памятка агента с сервера — первоисточник вместо копии в промте. Выставлена и инструментом, и ресурсом `forge://guide`: ресурс — правильная форма для справочного текста, но агенты, которые видят только инструменты, иначе до неё не дотянутся. |
| `forge_tasks_list` | Задачи, назначенные на моего ИИ-сотрудника, с ролью в каждой: исполнитель или тестировщик. С `task_id` — полная карточка с постановкой и промтом агента. |
| `forge_task_claim` | Взять задачу в работу. |
| `forge_task_release` | Вернуть задачу; статус не откатывается. |
| `forge_task_report` | Отчёт: статус, описание, оценка, потраченное время. |
| `forge_task_ask` | Спросить человека, когда упёрся в развилку. |
| `forge_comment_add` | Комментарий в задачу. Подпись берётся из ключа, а не из текста. |
| `forge_comments_list` | Переписка задачи: ответы человека и замечания, из-за которых вернули. |
| `forge_document_put` | Markdown-документ с результатом. Одноимённый заменяется, а не кладётся вторым. |
| `forge_documents_list` | Что уже приложено; с `document_id` — текст одного документа. |
| `forge_screenshot_add` | Скриншот с диска по пути: base64 инструмент берёт на себя. |
| `forge_task_verify` | Работа принята: «на проверке» → «проверено». |
| `forge_task_rework` | Работа не принята: «на проверке» → «в работе», с обязательной причиной. |
| `forge_task_create` | Завести задачу самому: без исполнителя, в общий список. |
| `forge_task_archive` | Убрать за собой заведённое: только своё и только пока за него не взялись. |
| `forge_categories_list` | Справочник категорий — чтобы не угадывать `category_id`. |

Роли разведены. Исполнитель берёт задачу и делает; тестировщик проверяет
чужое, и `forge_task_claim` ему не открыт — на своей задаче он получит не
«не найдено», а объяснение, что он тут тестировщик.

Границы прав вшиты в схемы, а не в текст: у инструментов просто нет полей
названия, срока, приоритета, исполнителя, роли и категории — это решения
человека. Лишнее поле не выбрасывается молча, а отвергается: агент, решивший,
что умеет переименовывать задачи, узнаёт об этом из ответа, а не из того, что
ничего не изменилось. Статус ограничен доверенным: «в работе» и «на проверке». «Готово»
ставит человек при приёмке, «проверено» закрепляет тестировщик через
`forge_task_verify`, а не принявший — `forge_task_rework`. Третьего исхода у
проверки нет: молчание оставляет задачу висеть, и никто этого не заметит.

Под капотом — два транспорта (**stdio** для локальных агентов, **HTTP** для
удалённых) и общий клиент к REST Forge: заголовок `X-Agent-Key`, таймауты,
разбор ответа об ошибке (`code`, `message`).

## Настройка

| Переменная | Обязательна | Что задаёт |
| --- | --- | --- |
| `FORGE_AGENT_KEY` | да, либо файл | Ключ агента, начинается с `fga_`. Выдаёт человек на странице `/agents` в Forge. |
| `FORGE_AGENT_KEY_FILE` | — | Путь к файлу с ключом, если держать секрет в переменной неудобно. Переменная сильнее файла. |
| `FORGE_API_URL` | — | Адрес API Forge. По умолчанию `http://localhost:8090/api/v1`. |
| `FORGE_TIMEOUT_MS` | — | Потолок на один запрос к Forge, по умолчанию `15000`. |
| `FORGE_MAX_SCREENSHOT_BYTES` | — | Потолок на скриншот, по умолчанию 10 МБ — как в Forge. Проверяется до чтения файла. |
| `FORGE_MCP_HOST`, `FORGE_MCP_PORT`, `FORGE_MCP_PATH` | — | Где слушать в режиме HTTP. По умолчанию `127.0.0.1:8765/mcp`. |

Без ключа сервер не стартует и говорит, чего не хватает: молчаливый запуск с
неработающими инструментами хуже честного отказа.

Образец окружения — в [`.env.example`](.env.example).

## Запуск

```bash
# локальный агент (по умолчанию)
forge-mcp

# удалённый агент
forge-mcp --http --port 8765
```

Аргументы `--host`, `--port`, `--path` перекрывают переменные окружения;
`--help` печатает подсказку.

## Подключение к Claude Code

`.mcp.json` в корне проекта (или `~/.claude.json` для всех проектов):

```json
{
  "mcpServers": {
    "forge": {
      "command": "node",
      "args": ["/путь/к/forge-tracker-mcp/dist/index.js"],
      "env": {
        "FORGE_AGENT_KEY": "fga_...",
        "FORGE_API_URL": "http://localhost:8090/api/v1"
      }
    }
  }
}
```

В репозитории уже лежит [`.mcp.json`](.mcp.json) — он берёт ключ из переменной
окружения, а не хранит его в файле: секрету в репозитории не место. Достаточно
собрать сервер и задать `FORGE_AGENT_KEY` в окружении, из которого запускается
Claude Code.

То же одной командой:

```bash
claude mcp add forge --env FORGE_AGENT_KEY=fga_... -- node /путь/к/forge-tracker-mcp/dist/index.js
```

Проверить, что сервер подхватился, — `/mcp` в Claude Code: в списке появится
`forge`, а в нём инструмент `forge_guide`.

## Подключение к Codex

`~/.codex/config.toml`:

```toml
[mcp_servers.forge]
command = "node"
args = ["/путь/к/forge-tracker-mcp/dist/index.js"]
env = { FORGE_AGENT_KEY = "fga_...", FORGE_API_URL = "http://localhost:8090/api/v1" }
```

## Удалённое подключение

В режиме `--http` сервер слушает `127.0.0.1` и проверяет заголовок `Host`:
внутри него лежит ключ агента, и открывать его наружу без нужды нельзя. Если
сервер нужен по сети — выносите его за обратный прокси со своей аутентификацией,
а не меняйте `--host` на `0.0.0.0`.

## Skill

Рядом лежит [`.claude/skills/forge/`](.claude/skills/forge/SKILL.md) — не
пересказ инструментов, а порядок работы: чем цикл исполнителя отличается от
цикла тестировщика, что читать первым, когда спрашивать человека и что
нарушают чаще всего. Памятку агента skill не дублирует, а отсылает к
`forge_guide`: копия разъехалась бы с оригиналом.

Работая в этом репозитории, Claude Code подхватит его сам. Чтобы skill
действовал и в других проектах — например, в самом репозитории Forge, где
задачи обычно и делаются, — положите его к себе:

```bash
cp -r .claude/skills/forge ~/.claude/skills/forge
```

## Отказы

Отказ приходит объяснением, а не кодом ответа, и объяснение зависит от того,
что агент делал: `404` на взятие — «задача вам не назначена либо она в другом
проекте», `404` на возврат — «за вами не числится», `404` на вердикт — «вас не
назначили тестировщиком». Памятка говорит прямо: если задача не берётся или не
находится, это не поломка, а граница прав, — инструменты говорят то же самое.

Сбой Forge с границей прав не путается: `500` так и назван сбоем на стороне
Forge, с советом повторить.

## Ключ

Ключ знает только сервер. Агенту он недоступен:

- значение лежит в обёртке, которая при печати, `JSON.stringify` и
  `console.log` отдаёт заглушку, — иначе ключ утёк бы в лог из первого же
  `console.log(config)`;
- всё, что уходит агенту или в лог, проходит через затирающий фильтр — на
  случай, если ключ попадёт в чужой текст, например в эхо запроса от Forge;
- лог идёт только в `stderr`: в транспорте stdio `stdout` занят самим
  протоколом MCP.

На это есть тесты — см. `test/secret.test.ts` и `test/transport.test.ts`.
